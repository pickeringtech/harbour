# Code of Conduct

## Be kind. Build useful things.

Harbour's rule is simple: be kind.

In the spirit of “Matz is nice and so we are nice,” treat the people around
this project as collaborators. Be curious, direct, patient, and generous.
Disagree with ideas without belittling people. Assume good faith where it is
reasonable, listen when somebody describes an impact you missed, and correct
mistakes without turning every conversation into a contest.

We are building Harbour because parallel, agentic development should help
people make genuinely useful and exciting things. Contributions that improve
that experience are welcome, whether they are code, documentation, bug
reports, questions, or a thoughtful “this is too complicated.”

Harbour is deliberately focused. It will not try to be everything to everyone.
Saying no to a feature, integration, or abstraction can be responsible project
stewardship rather than a rejection of the person proposing it. Maintainers
should explain those decisions plainly, and contributors should respect them
even when they would have chosen differently.

## Human judgment

No document can enumerate every way people can help or harm a community. We
will use human judgment, considering context, severity, and patterns of
behaviour. Personal attacks, harassment, intimidation, deliberate disruption,
or exposing somebody's private information are incompatible with the simple
request to be kind.

If a conversation goes wrong, maintainers may ask people to change course,
edit or remove material, lock a discussion, or limit participation. The aim is
to restore healthy collaboration and protect the people doing the work—not to
build a bureaucracy around punishment.

Report conduct concerns privately rather than opening an issue:

- For a GitHub comment, use its three-dot menu and choose **Report content**.
  The report is visible to both repository administrators and not to the
  reported author.
- For conduct that is not attached to reportable GitHub content, email
  [Richard Pickering](mailto:richard.pickering@hotmail.co.uk). Include links,
  screenshots, the impact, and any immediate safety concern.
- If the concern involves Richard or reporting to a repository administrator
  would be unsafe, use [GitHub's private abuse
  report](https://support.github.com/contact/report-abuse) instead.

Reports will be acknowledged within five business days. Maintainers will limit
access to the report, avoid public disclosure without the reporter's consent,
and recuse anyone named in it. The maintainer response process is documented in
[the security and moderation runbook](docs/maintainer-security.md).

Use good judgment. Leave the project and its people better than you found
them. Then go build something cool.
